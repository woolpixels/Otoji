# 开发文档

面向贡献者：版本号规则、发布步骤、命令、桌面版打包、界面约定与实现要点。使用说明见 [README](../README.md)。

## 版本号

当前 **v0.2.1**。版本号只写在 `app/package.json` 的 `version` 一处：窗口左上角的版本号、Mac 安装包的文件名（`Otoji-<版本>-arm64.dmg`）和应用信息都从这里读取。每次发布在 `CHANGELOG.md` 最上面加一条记录。

采用 `主版本.次版本.修订号` 三段，从小往大递增：

| 段位 | 什么时候加一 | 例子 |
| --- | --- | --- |
| **修订号** | 不改变能做的事：修 bug、调文案与样式、性能优化、兼容性修复 | 0.2.0 → 0.2.1 |
| **次版本** | 多了能做的事：新增页面或功能、新的导入 / 导出选项、明显的流程改动 | 0.2.1 → 0.3.0 |
| **主版本** | 产品形态变了：新增或去掉一个模式、旧习惯不再适用；功能稳定后的首个正式版为 1.0.0 | 0.9.0 → 1.0.0 |

- 低位进位时高位不变、低位归零（0.2.9 → 0.3.0 → 1.0.0）。
- 一次发布里既有新功能又有修复，按最高的那一档算，不再单独加修订号。
- 1.0.0 之前的 0.x 阶段，界面和流程仍可能调整。

**发布步骤**

1. 按上表改 `app/package.json` 的 `version`。
2. 在 `CHANGELOG.md` 最上面写一条：版本号、日期、用户能感知到的变化。
3. 执行 `npm run lint && npm test`，再执行 `npm run dist` 打包。
4. 打开 `app/release/mac-arm64/Otoji.app` 确认左上角的版本号正确，再分发 dmg。

## 常用命令

在项目根目录执行即可，根目录的 `package.json` 会把命令转给 `app/`。

```bash
npm install --prefix app   # 首次使用：安装依赖
npm run dev                # 开发服务器：http://localhost:5173
npm run build              # 输出到 app/dist/，可当静态页面部署
npm run lint
npm test                   # 纯逻辑单元测试（时间码、排序、容器探测等）
npm run desktop            # 以桌面窗口运行（不打包）
npm run dist               # 打包 Mac 应用
npm run icon               # 重新生成应用图标
```

`dist/` 需要通过 HTTP 访问（编码用 Web Worker，直接双击打开 `index.html` 不行）。

## Mac 桌面版

- 打包产物：`app/release/Otoji-<版本>-arm64.dmg`（安装包）和 `app/release/mac-arm64/Otoji.app`，仅 Apple 芯片（arm64）。
- 基于 Electron（`app/electron/main.cjs` + `preload.cjs`）。页面通过私有协议 `otoji://` 加载 `dist/`，编码 Worker 与 ffmpeg.wasm 的行为与浏览器一致；字体、解码器都在包内，离线可用。
- 窗口没有系统标题栏，红绿灯浮在顶栏左侧；拖动顶栏即可移动窗口。
- 导出直接存入「下载」文件夹（重名时自动加序号，如 `xx (2).mp3`），完成页可「在访达中显示」。
- **签名**：没有使用 Developer ID，只做了本机 ad-hoc 签名（Apple 芯片上运行所必需）。首次打开如被系统拦截，在访达里右键 Otoji.app → 打开。
- **图标**：Logo 原图是 `design/icon.png`（正方形，无透明通道）。`npm run icon` 把它放进 macOS 风格的圆角底（底色 `#faf9f5`，与 Logo 背景一致），生成 `app/build/icon.icns`、`icon.png` 与网页图标 `app/public/favicon.png`。换 Logo 后依次执行 `npm run icon` 和 `npm run dist`；已装过旧版时访达 / 程序坞可能因缓存仍显示旧图标，重装应用即可。
- 打包直接使用 `node_modules` 里已安装的 Electron（`build.electronDist`），不需要联网下载。

## 界面约定

- 单窗口。顶栏左侧是 Otoji、版本号和面包屑「首页 / 当前功能」，点「首页」或 Otoji 回到首页切换功能（两边的进度都保留）；右侧是当前界面的快捷键提示，只在编辑时显示。
- **首页**（初始状态）：两张卡片分别对应提取和拼接，可点击选择或拖入。拖到页面任意位置时按类型分开处理：视频去「提取音频」，音频去「拼接音频」（混合拖入时两边同时导入，停在提取）。某个 Tab 里已有内容时，卡片上显示「继续：…」。点左上角 Otoji 回到首页，不清空任何进度。
- 各 Tab 的空状态本身就是拖放区；导入后原地变成编辑界面。没有弹窗、设置页、向导。
- **导出完成页**：导出后在原地替换编辑界面，显示文件名、时长、音质、大小、采样率与声道，以及保存位置（「下载」文件夹）；可直接试听刚写入的 MP3。底部：「← 返回调整」（选区与列表都还在）、「另存一份…」、提取页另有「送入拼接」；主按钮是「处理下一个视频」/「开始新的拼接」，清空当前 Tab 并打开文件选择。
- 底部操作栏：左侧参数，右侧唯一的朱色主按钮。未就绪时置灰。
- 视觉：纸白 `#F5F1E8`、墨 `#1D1C1A`、朱 `#C24A22`、灰 `#D9D2C3`；界面文字 Noto Sans SC，时间码 / 时长 / 大小用 JetBrains Mono；圆角 10px。字体随包内置。

## 提取音频

1. **导入**：拖入或选择一个 MP4 / MOV（也接受 M4V）。再次拖入即替换；新文件读不出来时保留原来的。
2. **提取**：先读容器头（`src/lib/probe.ts`）拿到编码、采样率、声道数，没有音轨时直接提示；再按源采样率解码，保证不被重采样。
3. **裁切与试听**：拖动波形两端手柄，或在「开始 / 结束」里输入 `mm:ss.s` 或秒数（如 `72.5`），超出范围自动夹紧；开始 ≥ 结束时输入框标红并禁用导出。只播放选区；松开手柄后从该点前 2 秒开始试听。
4. **默认裁切**：导入后结束时间默认为「全长 − 3 秒」，去掉短视频末尾常见的几秒片尾（不足 4 秒的视频保留全长）。结束时间短于原视频时，「结束」输入框以朱色高亮，下方用小字显示相较原结尾裁掉的时长，如 `−00:03.0`。按默认值裁切不计入文件名里的区间后缀。
5. **导出**：128 / 192 / 320 kbps，默认 192，旁边实时显示预计大小。保留源声道数与采样率（MP3 上限为立体声、48 kHz，超出时才转换）。文件名默认「视频名.mp3」，有裁切时追加区间，如 `_0112-0427`。
6. **送入拼接**：把当前选区直接加到「拼接音频」列表末尾（不经过编码）。

快捷键（顶栏右侧有提示）：`空格` 播放 / 暂停 · `I` / `O` 把播放头设为开始 / 结束 · `⌘S` 导出。

## 拼接音频

- **导入**：可多选、可拖入；新文件按文件名自然排序（2 在 10 之前）后追加到末尾。同一文件不会重复导入。以 MP3 为主，也能读 M4A / WAV / FLAC / OGG。
- **排序**：按住 `≡` 拖动整行，落点显示插入线；或选中后 `⌥↑` / `⌥↓`。`⌫` 删除选中行。
- **静音间隔**：默认间隔作用于所有缝隙，预设 0 / 0.5 / 1 / 2 秒，或自定义 0–10 秒（步进 0.1）。点击任一缝隙可单独覆盖，覆盖后以朱色标出，可一键恢复默认。单独设置跟随它前面那一段移动。首尾不加静音。
- **试听**：按当前顺序与间隔连续播放，无需先合并；进度条按段显示，当前段在列表中同步高亮；双击某行从该段开头播放，点进度条某段从该处播放。播放中调整顺序或间隔，下一段起生效。
- **导出**：全部解码成 PCM 后整体重新编码，拼接处没有 MP3 首尾补帧造成的空隙。采样率统一为其中最高的，单声道升为立体声。文件名为「第一段名_合并N段.mp3」。

## 技术要点

| 环节 | 做法 |
| --- | --- |
| 解码 | `decodeAudioData`，上下文按源采样率创建；失败时按需加载 ffmpeg.wasm（约 32 MB，单独分包、随应用一起打包，离线可用） |
| 编码 | lamejs（`@breezystack/lamejs`）在 Web Worker 中编码，音频分块送入，显示进度，可随时取消 |
| 试听 | `AudioBufferSourceNode` 依次排程，间隔即排程偏移（`src/lib/player.ts`） |
| 保存 | 导出直接下载到「下载」文件夹，不弹对话框（浏览器若设置了「下载前询问保存位置」则以设置为准）。完成页的「另存一份…」在 Chromium 系用 File System Access API 选择位置，其他浏览器再次下载 |
| 长音频 | 超过 30 分钟时提示内存占用；分块流式解码留待后续版本 |

## 产品决策

- 打包为 Mac 应用（Electron）。
- 其余决策：提取结果可一键送入拼接；提取一次一个视频；拼接提供三档音质、默认 192；段落衔接处不做淡入淡出。
